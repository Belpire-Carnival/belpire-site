# CLAUDE.md — belpire-site

Coding notes for Claude. Operational setup (GitHub, Cloudflare, secrets) is documented privately, not in this repo.

## What this is
belpire.com, the public website for the **Belpire Carnival** Discord community (multiplayer horror and party games). Gothic-carnival theme: owners are the **RingMaster** and **RingMistress**.

- `site/` is plain HTML, CSS and vanilla JS. No framework, no bundler, no npm dependencies. Keep it that way unless asked.
- Games are grouped into three **tents**: `horror` (crimson), `party` (gold), `other` = "The Sideshow" (slate).
- `worker/` is the only server code (`/api/*`, `/auth/*` and a scheduled refresh). It powers the Star Citizen division's live panels (`site/bureau/rsi1/`, `GET /api/star-citizen`, which also answers on the subdomain). Parsers are pure functions in `worker/rsi.js`, tested in `worker/test/`. Fetch each external source politely (at most once per refresh), never hotlink RSI media or use RSI/CIG logos, and keep the unofficial-fan-site disclaimer in the footer.
- **Discord invite gate:** everything is public except the Discord invite. `worker/auth.js` runs "Verify with Discord" (OAuth2, scopes `identify email`): it requires `verified === true`, revokes the Discord grant straight after the check, and sets an encrypted 30-day cookie holding only user ID, display name and timestamps. `/api/invite` returns the invite to a valid session; `site/join/` is the box office page. The invite lives only in a runtime secret, never in the repo or page source. Never store or log the email. All "Join" buttons link to `/join/`; the top-right nav button is "Sign in" (see below).
- **Jackbox page** (`site/jackbox/`): the collection lives in `site/jackbox/packs.json` (validated by `worker/test/jackbox.test.mjs`); picker logic is pure in `pick.js`; the build adds store art and recent official news for those app IDs to `feed.json` under `jackbox` (never posted to Discord). Game-show styling in `jx.css` on top of the shared styles; original art only, no Jackbox logos or characters.
- **Game search** on the home page: `site/search.js` (pure, tested in `worker/test/search.test.mjs`) indexes `feed.tracked` (every favorite), the news items and upcoming games; `site/app.js` is an ES module and runs the ARIA combobox.
- **The Big Tent** (`site/big-tent/`, API in `worker/polls.js`): game-night polls. Several polls can run at once (up to `MAX_ACTIVE_POLLS` = 8, for a series of event nights); each has its own ballots, the page shows tabs (`?poll=<id>` keeps the choice) and Backstage shows tools per poll. Anyone in the Discord server votes (ranked choice, 4-3-2-1 points, ties by first places); holders of `POLL_MANAGER_ROLE_IDS` (RingMaster, RingMistress, Carnival Guard, Fortune Teller) open, close, schedule and cancel from **Backstage** (`site/backstage/`, a separate staff page with a short brief on what each tool does; `gn.js` runs it when `<body data-page="backstage">`, showing a sign-in or "Staff only" gate to everyone else). It holds the poll tools, Game Night pass requests, the Hall of Oddities review queue and the Discord connection check; the API enforces the role on every action (role-dependent actions re-read it from Discord). Ringleaders get a "Go Backstage" link on The Big Tent. Backstage also has **The Green Room** (`worker/staff-chat.js`, `site/big-tent/staff-chat.js`, `/api/backstage/messages`): a staff thread in D1 `staff_messages`; each message is posted by the bot to `MOD_CHANNEL_ID` (no pings), authors can delete their own (here and in Discord), 10 per minute per person, purged after 90 days (cron). Membership and roles are read with the bot (`worker/discord-bot.js`), never stored. Opening a poll has the bot post it to #general (`openMessage`); Ringleaders resend it as a reminder with the vote count from Backstage (`POST /api/polls/:id/post`) or `/poll`, at most once per 10 minutes per poll (`open_posted_at`, claimed atomically). Closing posts results to #general; scheduling creates a voice-channel scheduled event in The Main Stage and posts again to #general. Data lives in D1 (`DB`, `worker/poll-db.js`, tables created on first use); ballots are purged 90 days after the poll opens (cron). Results stay hidden while voting is open. Voters drag games onto the four slots (pointer events; touch is press-and-hold, with edge auto-scroll) or tap a game then a slot; keyboard works through the same buttons. A carnival ticker across the top of the page scrolls the open poll and booked nights (static under reduced motion; a hidden list carries the text for screen readers), with Discord links and Ringleader tools just below it. Signed-in members see who has voted (`voters`: names + whether they used the wheel), never anyone's picks. The **Wheel of Doom** (`POST /api/polls/:id/doom`) picks up to 4 horror/party/Jackbox candidates server-side with crypto randomness and saves a locked ballot; the page only animates the result. Cover art comes from `feed.tracked[].image` / `feed.jackbox.images`, allowed only from Steam image hosts (`safeArt`). Tests run the real SQL on node:sqlite (`worker/test/helpers/d1.mjs`).
- **Hall of Oddities** (`site/oddities/` page for uploads, review and the full gallery; a showcase on the home page `#oddities`; both run `site/oddities.js` via `data-oddities="full|showcase"`; API in `worker/oddities.js`). Two wings: pictures ("The Gallery of Grotesques") and clips ("The Scream Reel": silent hover preview, sound on click). Every upload needs a short title (≤ 60 chars) and shows "Uploaded by <Discord name>". Members toggle reactions (like, love, laugh, scream, dead, angry); only totals are public. Pictures: PNG/JPEG/WebP ≤ 10 MB, or "Take a screenshot" via `getDisplayMedia`. Clips: MP4/WebM ≤ 500 MB, uploaded to R2 in 25 MB multipart parts. `worker/oddity-check.js` is pure and tested: type comes from the file's bytes (BMP, SVG, GIF and everything else refused), pixel limit, metadata/GPS stripped, titles cleaned. Pictures are scanned with Workers AI (`AI`, Llama 4 Scout vision): allow → live, block → refused, unclear or scan failure → queue. Fictional/game gore is allowed; nudity, real-world gore, hate and personal info are not. Every member's clip waits for a Ringleader; Ringleaders' own pictures and clips skip the scan and the queue (file checks still apply). The review queue shows on `/oddities/` and on the Backstage page (`site/big-tent/oddity-review.js`). Three member reports pull an item back to the queue. Files live in R2 (`ODDITIES`), rows in D1 (`worker/oddity-db.js`). Media is served by the Worker with `nosniff` and a sandbox CSP; never serve uploads from `site/`.
- **Live banner** (`site/live.js` on the home page and The Big Tent, API `GET /api/live` in `worker/live.js`): every 30 s the page asks whether a Ringleader is using Go Live in The Main Stage. The Worker checks each user in the `RINGLEADER_IDS` runtime secret with Discord's Get User Voice State (no list endpoint exists), caches 30 s in KV, and returns display names, the current game night if one is under way, and a `discord.com/channels/…` join link. Never commit those IDs.
- **Game Night passes** (`worker/passes.js`, `site/big-tent/passes.js`): the Game Night role lets members into The Main Stage; Ringleaders approve each one on the Backstage page. Members ask on The Big Tent (bot adds `GAME_NIGHT_PENDING_ROLE_ID`) or by answering Yes in Discord onboarding (gives the Pending role; the cron lists members, which needs the Server Members intent, and queues them; anyone with both roles just loses Pending). A note goes to `MOD_CHANNEL_ID` (optional). Approve → `GAME_NIGHT_ROLE_ID` on, Pending off, DM; deny → Pending off, optional reason by DM. Requests live in D1 `pass_requests`. The live banner sends members without the role to the pass instead of the channel. The bot needs Manage Roles and a role above both.
- **Header** (`site/header.css`, loaded after each page's own stylesheet on belpire.com): pinned to the top while scrolling; at 960px and below `site/account.js` folds the links into a Menu button (adds `.js-nav`; without JS the links simply wrap). Account and Menu dropdowns close each other.
- **Sign in** (`site/account.js`, on every page with the main nav): the top-right button is a plain "Sign in" link to `/auth/login` (returns to the current page; `/` and `/join/` go to `/me/`). Signed in, it becomes a menu built from `GET /api/me` (`worker/me.js`: membership, pass status, unvoted polls, live status, ticket summary, and for Ringleaders counts of what's waiting Backstage; Green Room "new message" uses a `localStorage` seen-marker set by `staff-chat.js`).
- **Slivers** (the currency members see; every ticket holds a sliver of someone's life, so the physical ticket, the Ticket Booth and "Get your ticket" keep their names. Code, API paths and D1 tables still say `tickets`; don't rename those, the data lives there. Snacks at the Concession Tent (`/concession`, `RULES.snacks`) cost Slivers and are counted by ledger ref for the curd Feats.) (`worker/tickets.js`, `worker/ticket-db.js`, prizes in `worker/prizes.js`, page `site/me/` "Your Ticket Booth", Backstage panel `site/big-tent/prizes-staff.js`): one bank in D1 (`ticket_wallets` running balance + `ticket_ledger` every change, with a unique `ref` so retries and cron runs never pay twice). Earn: daily punch card (streak bonus, days roll over at midnight Eastern), Find the Pea (shell game, 5 a day), Ring Toss (pick a row; odds and prizes per row in `RULES.ringRows`, 5 a day) and the High Striker (puck height 1–10 from `RULES.strikerTiers`, bell = jackpot, 3 a day), all decided server-side with crypto randomness and shown with the odds on the page, game-night attendance (check in while in The Main Stage; the cron pays every 10 minutes while still there and not deafened, capped per show; only checked-in people are ever looked up), Ringleader awards. Spend: Prize Booth orders wait Backstage (Mark done → DM; Refund → tickets back + DM). "Put a game on the ballot" orders arrive pre-ticked in the Backstage poll form and complete when a poll opens with that game. Midway High Scores rank tickets won (lifetime), with an opt-out; every Sunday at noon Eastern (`POST_HOUR_ET`) the cron posts the week's top earners and the all-time leaders to `ANNOUNCEMENTS_CHANNEL_ID` once (`ticket_posts` claims the week), and Ringleaders can post it on demand from Backstage (`POST /api/tickets/post-scores`). Rules/amounts live in `RULES` in `tickets.js`. **Sliver coins** (`worker/coins.js`, the one ladder): 15 tiers named after the districts, The Gate (0) to The Witching Hour (666,666), picked by **lifetime** Slivers won, so a coin never goes back down (the owner chose this, and chose to show all 15 names on the site). `summary()` (so `/api/me` and the wallet) and each High Scores row carry `coin`; `/api/tickets` sends the ladder as `coins` so the Ticket Booth can recompute after a game. Shown in the header's account button, on Your Ticket Booth (your coin, progress to the next, and the whole ladder), beside each High Scores name, and as the thumbnail on `/slivers`. Art: `site/assets/slivers/<slug>-64.webp` (header), `-128.webp` (ladder, High Scores) and `-384.webp` (the big coin, `/slivers`), owner-supplied coins cut out to transparent squares. Show them exactly as painted: no filters, tints or dimming, even for coins not reached yet.
- **Slash commands** (`worker/interactions.js`, `POST /api/discord/interactions`, the app's Interactions Endpoint URL): Ed25519 signature check with the `DISCORD_PUBLIC_KEY` runtime secret (5-minute timestamp window), answers immediately with no gateway connection. `/slivers`, `/punch-card`, `/find-the-pea`, `/ring-toss`, `/high-striker`, `/checkin`, `/concession`, `/high-scores`, `/prizes`, `/redeem`, `/poll` and `/give-slivers` (Ringleaders, checked against `POLL_MANAGER_ROLE_IDS` from the interaction's member roles). Same functions as the website, so both always agree. Register or update them with `npm run commands` (`scripts/register-commands.mjs`, reads `DISCORD_APP_ID`, `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID` from the environment or the git-ignored `.env`).
- **Alpha tester sign-ups** (`worker/alpha.js`, buttons and a form through the same interactions endpoint) for a members-only Discord project. **That project lives only in Discord: never name or describe it in this repo, on the website, in commit messages or in PR text**, and never show anything about it on belpire.com (including Slivers earned there; the site only ever shows the balance). A pinned Discord post has a "Sign up for the alpha" button (`custom_id` `alpha:signup`, posted by the owner's local setup script with the Usher's token, so presses reach this Worker). Only holders of `ALPHA_ACCESS_ROLE_ID` get the form. Answers go **only to the server owner by DM** (owner read from Discord, never stored) with Approve/Decline buttons that only the owner can press; a staff channel would be visible to anyone with Administrator. Approve → `ALPHA_TESTER_ROLE_ID` + welcome DM; decline → kind DM, can retry after 30 days. D1 `alpha_signups` keeps ID, name, status and dates (never the answers); approved rows stay so early testers can be thanked later. A test fails if `alpha.js` names the project.
- **Bureau of Finality** (the community's multi-game org; FINTAC on RSI) lives at **bureau.belpire.com**. HQ (`site/bureau/index.html`) holds what's org-wide: creed, divisions, dossier, rules of engagement, command, enlist. Each game is a **division** with its own page and tab, codes in the form `DIV_<code>`: `rsi1/` Star Citizen (FINTAC on RSI/Spectrum), `se1/` Helldivers (the HD2 Clans clan), `bf1/` Battlefield, `tc1/` Tom Clancy (The Division, The Division 2, Ghost Recon Wildlands and Breakpoint) and `ds1/` Destiny (both forming). `sq1/` is **not a game**: it is the **Tactical Command Center (TCC)**, the Bureau's members-only Discord, with the last tab ("Command Center") and its own page about what members get. HQ's `#dossier` is the **Historical Record**: the org was founded April 9, 2026 (FINTAC), and its four eras map onto the divisions (I Origins 2026–2035 = TC1, II Escalation 2035–2099 = BF1, III Expansion 2100–2950 = RSI1, IV Cosmic Front 2950–beyond = SE1 and DS1); era art is `site/bureau/img/era-<n>.webp`, cropped from the owner's timeline mockup, and `site/bureau/record.js` reveals the cards and counts days since the origin event. Keep division subtitles and briefs consistent with those eras. Every page shares one header: gold lettering brand, bracketed in-page links, and an evenly spaced division tab bar (`aria-current` marks the open division). To add a division: copy a division folder, add its tab to the `.divs` nav on every page, add its card on HQ, and add it to the og-image list in `repo.test.mjs`. the same Worker serves it from `site/bureau/` by hostname (`worker/bureau.js`; `run_worker_first: true` so the Worker sees every request; shared `/fonts/`, `/og/` and icons pass through; `/api/*` and `/auth/*` go back to belpire.com; `belpire.com/bureau/` 301s to the subdomain; other hosts serve `/bureau/` as a folder for previews). Its own navy-and-gold look in `site/bureau/bureau.css`, with relative links so it works on both. HQ's hero is a canvas scene (`site/bureau/battle.js`: fighters over a planet and citadel, with a ground front in each lower corner; its other modes are a fallback for a division with no painted art). Each **division hero is owner-supplied painted art** (`site/bureau/img/scene-<code>.webp`, 1200x804, the painted title and buttons removed) in a `.stage` sized in CSS to cover the hero; crest, title, subtitle and motto are live and placed in image pixels (`calc(var(--sw) * n / 1200)`, per-scene numbers on `.stage[data-scene]`) so the official crest sits exactly on the painted one. `site/bureau/fx.js` animates each picture from hotspots measured on it (firelight, embers, smoke, radar sweeps, tank muzzle flashes and tracers for bf1; camera-feed static, map pings, scanning logs and live telemetry bars for sq1; lasers, explosion bursts and twinkling stars for rsi1; falling drop pods, red beams, blasts and lava glow for se1; muzzle flashes, tracers, embers and a camera feed for tc1; lasers, radar sweeps, meteors and void glow for ds1). The tc1 and ds1 posters were portrait, so they were widened to 1200x804 with blurred, darkened wings, and their crest sits above the title (`--ty` below `--cy`), plus a slow camera drift and pointer parallax; all of it stops under reduced motion and off-screen. If a scene picture changes, re-measure its hotspots and crest position. Division link previews are `site/og/bureau-<code>.jpg`. The crest in `site/bureau/img/` is the org's own logo (owner-supplied, used as is; the site's "gold" tokens are a matching brushed bronze); never RSI/CIG logos or ships. Star Citizen moved off belpire.com: DIV_RSI1 runs Operations, **The Comm Array** (tabs: Network Status and Comm-Link Feed), The theatre (contract notes + reporting in) and **The Quartermaster** (the community tools), from `site/bureau/rsi1/sc.js` + `tools.json`, `belpire.com/star-citizen/` 301s to `bureau.belpire.com/rsi1/`. Every other game division (se1, bf1, tc1, ds1) has its own **Quartermaster** of reference links in `site/bureau/<code>/tools.json`, drawn by the shared `site/bureau/quartermaster.js` (https links only; kinds: official, wiki, map, web, app, overlay, bureau), and the main nav's "The Bureau [TCC]" link goes straight to the subdomain.
- **Bureau Patches:** a game in `config/games.json` with a `division` (`se1`, `bf1`, `tc1`, …) keeps its Steam news in the feed tagged with that division; the Midway on belpire.com hides tagged games (`site/app.js`), and each division page shows its own in a Bureau Patches section (`site/bureau/patches.js`, reading `/data/feed.json`, which passes through on the subdomain).
- The Star Citizen **Toolbox** is data in `site/bureau/rsi1/tools.json`, validated by `worker/test/tools.test.mjs`. Only link official sources; never mirror downloads.

## Rules
- **This repo is public.** Never commit secrets, URLs that act as credentials, account names, internal IDs, dashboard click-paths or infrastructure runbooks. Comments explain code, not how the hosting is set up.
- Caching (`site/_headers`): fonts are immutable for a year (give a changed font a new file name); images under `ringleaders/`, `assets/`, `og/` and the icons cache a day with a week of stale-while-revalidate; JS/CSS revalidate on every load.
- `site/data/feed.json` is generated at build time and git-ignored. Never commit it.
- Render all external text with `textContent`; links must be `https:`. Never use `innerHTML` with data.
- Keep `site/_headers` (CSP) in sync if you add any new external origin. Allowed today: Steam image CDNs only. Fonts are self-hosted: `site/fonts/*.woff2` (Latin subsets, OFL, licences in `site/fonts/LICENSE.txt`) declared in `site/fonts.css`; pages preload Barlow 400 and Cinzel Decorative 900. Never add Google Fonts links back.
- GitHub Actions: GitHub-owned actions only, pinned to a full commit SHA with a `# vX.Y.Z` comment. Workflows default to no permissions; grant per job.
- Changes go through a PR from a branch, squash merge, signed commits, and the `test` check must pass.
- Accessibility: real `<button>`/`<a>` elements, visible focus, 4.5:1 text contrast, touch targets at least 44px, works at phone width.
- Use LF line endings (see `.gitattributes`).
- Browser scripts in `site/` are `.js` (ES modules where they import), never `.mjs`; JS and CSS are served with `max-age=0, must-revalidate` so a deploy reaches visitors immediately.
- `worker/test/repo.test.mjs` fails CI on merge-conflict markers or a `REPLACE_WITH_` placeholder in `wrangler.jsonc`.
- **Keep `site/privacy/` truthful.** Today the site has no analytics; its only cookies are the Discord sign-in ones, and the stored personal data is poll ballots (Discord ID, display name + picks, 90 days; members see voter names and Wheel of Doom use, never picks), Hall of Oddities uploads (file, title, Discord ID + display name, until removed), reactions (Discord ID + reaction), Game Night pass requests (Discord ID, name, outcome, optional reason), tester sign-ups (Discord ID, name, status, dates; form answers only go to the owner by DM), Ringleaders' Backstage messages (Discord ID, name, text; 90 days) and tickets (Discord ID, name, balance, ledger of earn/spend, game-night check-ins for 3 days, Prize Booth orders; High Scores show names, Slivers won and each member's Sliver coin to members, and names in the weekly announcements post, unless hidden). Any change to that (new cookies, new data from Discord, analytics, a new external origin) must update the Privacy Policy and its effective date in the same PR.
- **Page scenes:** The Big Tent, Your Ticket Booth and the Hall of Oddities each have a dim, fixed carnival backdrop (`<div class="scene" data-scene="bigtop|booth|sideshow">`, styles in `site/fx.css`, original SVG art in `site/assets/scenes/`). Keep them faint enough that text stays readable over them.
- **Visual effects are decoration only.** `site/fx.css` + `site/fx.js` load on every belpire.com page; the Bureau has its own (`battle.js`, `fx.js`). Every animation must switch off under `prefers-reduced-motion: reduce`; content must be readable if JS never runs; no inline styles or scripts (set CSS variables from JS); all art is original, never characters or designs from films or games (exception: the Bureau division scenes, which are the org owner's own supplied artwork).

## Common tasks
- Add a favorite game: `config/games.json` → `favorites` (`appid` from the Steam store URL, `tent`).
- Edit game nights or ringleaders: `site/index.html`. The Midway's upcoming games and patch notes show 6 items with a "Show more" button (`site/app.js`). Ringleader avatars are animated WebP files in `site/ringleaders/` (224×224); images cache for a day, so give a replacement a new file name and update the `<img>`.
- Link previews (Discord, social): each page has Open Graph tags pointing at a 1200×630 JPEG in `site/og/` (checked by `repo.test.mjs`). Original art only.
- Add a Jackbox box: append it to `site/jackbox/packs.json` (Steam app ID, year, games with player ranges and a style).
- Discord invite link: a runtime secret, changed in the hosting dashboard, not in code.
- Crew overlap (shared games + Sideshow search ideas): `npm run crew` on the owner's PC. Reads git-ignored `crew.local.json` and `STEAM_API_KEY`, writes git-ignored `crew-report.md`. Never commit crew Steam IDs or the report.
- Slivers: change amounts in `RULES` (`worker/tickets.js`); change prizes in `worker/prizes.js`, then run `npm run commands` so `/redeem` lists them.
- Before a PR: `npm run check`. Local preview: `npm run feed && npm run dev`.
